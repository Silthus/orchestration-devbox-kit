# Orchestration Wayfinder — T3 Code threads

Read this addendum when the conductor runs inside T3 Code, together with the runtime addendum. Grilling and prototype tickets get their own T3 thread in the sidebar: the human switches to it and works the ticket there, while the conductor keeps the rest of the frontier moving. All other ticket types dispatch through the runtime addendum.

The thread commands come from [`t3-kickoff`](../t3-kickoff/SKILL.md). Read it before the first thread. Below, `kickoff` means `bun ~/.agents/skills/t3-kickoff/scripts/kickoff.ts`.

## Cast

A T3 thread runs its model natively through T3. It is not a provider bridge, so the retired-cast rule in [`SKILL.md`](SKILL.md) does not apply to the thread's own model.

Follow **Casting** in [`SKILL.md`](SKILL.md) to choose the worker's model, then select the provider offering it. Pass both explicitly to `kickoff` so its CLI defaults do not replace the selection. A wrong slug makes `kickoff` list the offered slugs.

The retired-cast rule still binds every sub-agent the thread spawns, so restate it in the prompt.

## Start a thread

1. Write the worker prompt to a file. It carries everything a runtime worker prompt carries, plus the ticket type's terminal below. It tells the worker that the human talks to it in this thread.
2. Start the thread in the map's repository. Done when `kickoff` prints the thread id and `turn started`:

   ```sh
   kickoff --project <T3 project of the repo> --title "<type> #<id>: <ticket title>" \
     --provider <provider> --model <slug> --worktree new --base <default branch> --prompt-file <file>
   ```

   Start threads one at a time.

3. Record the locator on the ticket immediately:

   ```md
   <!-- orchestration-wayfinder-dispatch -->

   Runtime: T3 Code
   Thread: <threadId>
   Title: <thread title>
   ```

4. Arm the thread's waiter (see **Wake**).
5. Grilling only: cue the human once with the thread title, because grilling is live from the first turn. Record `<!-- orchestration-wayfinder-cue:t3:<threadId> -->` on the ticket.

## Terminals

**Grilling.** The worker grills the human live in the thread with `/batch-grill-me` and `/domain-modeling`. When the tree is exhausted, it posts the durable handoff comment, closes the ticket, and ends its turn with a one-line summary.

**Prototype.** The worker builds the prototype with `/prototype` on its `prototype/<name>` branch in its AFK stretch, then parks: the park comment, `wayfinder:awaiting-human`, and in the thread how to open the prototype and the one question it answers. Each human reply is feedback: the worker iterates, pushes, and ends its turn. An architecture prototype parks with its first round of open decision cards as the pending question, and each round of answers is feedback. The human's explicit acceptance is the only resolution. On acceptance, the worker pushes the branch, posts the durable handoff with the decision and the branch pointer, removes `wayfinder:awaiting-human`, and closes the ticket.

## Wake

Each thread has exactly one live waiter. The waiter is the lane's event source and its deadline wake for the lane contract:

```sh
kickoff wait --thread <threadId> --after <last seen turn> --timeout <cap in seconds, at most 5400>
```

Run it as a background command; its exit is one notification. Omit `--after` for the first wait. The cap bounds one worker turn, not the human's reply time.

On each exit, apply the **Wake law** to the tracker first, then act on the ticket:

- **Closed** → verify the durable handoff, then `kickoff archive --thread <threadId>`. Archive is the retirement: it clears the sidebar, and the ticket keeps the handoff. Arm no new waiter.
- **Open, first `wayfinder:awaiting-human`** → cue the human once with the thread title and the pending question. Record the `t3` cue marker. Re-arm with `--after <turn>`.
- **Open, any other state** → the thread is mid-conversation. Re-arm silently with `--after <turn>`.
- **`gone: true` with the ticket open** → the human archived or deleted the thread. Mark the lane orphaned, reconcile the ticket per the lane contract, and cue the human once to ask whether to redispatch it.
- **Exit 1** → the T3 server did not answer. Re-arm once with the same `--after`. A second failure is an orchestration blocker: record it on the ticket and cue the human once.
- **Exit 2** → if `state` is `running` and `startedAt` is older than the cap, `kickoff stop --thread <threadId>`, mark the lane orphaned, and reconcile per the lane contract. Otherwise re-arm with the same `--after`.

## Recovery

T3 threads survive a conductor resume. A ticket whose latest locator says `Runtime: T3 Code` recovers here, not through the runtime addendum.

For each such open ticket, reconcile the tracker first, then run `kickoff status --thread <threadId>`:

- Not gone → arm one waiter: with `--after <turn>` when the latest turn has ended, without `--after` while it runs.
- Gone → handle it as `gone: true` under **Wake**.

An invalidated ticket with a thread: record the invalidation, clear `wayfinder:awaiting-human`, then `kickoff archive --thread <threadId>`.
